# Регламент заполнения модального окна «Переместить/Переназначить технику»

## 1. Назначение

Документ фиксирует фактическую логику заполнения модального окна на странице `Учет ТС` и поведение автоподтягивания данных после выбора нового пользователя.  
Документ используется для проверки и воспроизведения функционала на другой машине без ручного ввода значений.

## 2. Где находится функционал

- Верстка модального окна и клиентская логика: `ias_uch_vnii/views/arm/index.php`
- Инициализация кнопки открытия модального окна в гриде: `ias_uch_vnii/web/js/arm/ag-grid.js`
- Серверные методы, используемые модальным окном: `ias_uch_vnii/controllers/ArmController.php`

## 3. Открытие модального окна

1. Пользователь отмечает строки в таблице `Учет ТС`.
2. Нажимает кнопку `Переместить/Переназначить`.
3. Вызывается `openReassignModal(ids)`:
   - очищаются поля формы;
   - режим операции устанавливается в `reassign`;
   - кнопка `Сохранить` блокируется до появления изменений;
   - выполняется загрузка данных по выбранной технике через `POST /arm/get-selected-info`.

## 4. Источники автоподтягивания данных

### 4.1 Обычное переназначение (`operation_mode = reassign`)

При изменении поля `Ответственный` (`reassignUserId`) вызывается:

- `GET /arm/user-primary-location?user_id=<ID>`

Логика:

- если найдено помещение, где у выбранного пользователя больше всего единиц техники, это `location_id` автоматически подставляется в поле `Помещение` (`reassignLocationId`);
- автоподстановка выполняется только при выбранном пользователе `!= 0` и только в режиме `reassign`;
- после подстановки пересчитывается предпросмотр изменений и доступность кнопки `Сохранить`.

### 4.2 Перемещение компонента (`operation_mode = move_component`)

При выборе пользователя-владельца целевого ПК (`targetSystemBlockUserId`) выполняются два действия:

1. Ответственный автоматически устанавливается равным выбранному пользователю (поле `reassignUserId`).
2. Загружается список системных блоков этого пользователя через:
   - `GET /arm/system-blocks&user_id=<ID>`

После выбора конкретного системного блока (`targetSystemBlockId`):

- из атрибута `data-location-id` выбранного пункта берется `location_id`;
- это значение автоматически подставляется в поле `Помещение` (`reassignLocationId`).

### 4.3 Увольнение (`operation_mode = dismissal`)

Автоподтягивание помещения по пользователю не выполняется.  
Изменения зависят от выбора:

- `Передать технику пользователю` (`dismissalTargetUserId`), или
- `При увольнении отправить технику на склад` (`dismissalToWarehouse`).

## 5. Как определяется помещение по пользователю

Серверный метод `actionUserPrimaryLocation()` выбирает `location_id` как наиболее частое помещение среди не удаленной техники пользователя:

- фильтр: `responsible_user_id = user_id`, `is_deleted = false`, `location_id is not null`;
- группировка по `location_id`;
- сортировка по количеству по убыванию;
- берется первая запись.

Если данные не найдены, возвращается `location_id = null`, поле `Помещение` не меняется.

## 6. Когда кнопка «Сохранить» активна

Кнопка активируется только при валидных изменениях относительно режима:

- `reassign`: изменено хотя бы одно из полей `Ответственный`, `Помещение`, `Статус`;
- `move_component`: выбраны и пользователь целевого ПК, и целевой системный блок;
- `dismissal`: установлен флаг отправки на склад или выбран пользователь передачи.

## 7. Что проверить, если на другой машине автоподтягивание не работает

1. **Актуальность кода**
   - проверить, что файл `ias_uch_vnii/views/arm/index.php` содержит:
     - `window.agGridArmUserPrimaryLocationUrl`
     - функции `applyDefaultLocationForReassign`, `fetchSystemBlocksForUser`, `applyDefaultLocationFromTargetSystemBlock`.
2. **Наличие маршрутов и методов на сервере**
   - проверить доступность эндпоинтов:
     - `GET /index.php?r=arm/user-primary-location&user_id=<ID>`
     - `GET /index.php?r=arm/system-blocks&user_id=<ID>`
     - `POST /index.php?r=arm/get-selected-info`
3. **Данные в БД**
   - у выбранного пользователя должна существовать техника с заполненным `location_id`;
   - в режиме `move_component` у пользователя должен быть хотя бы один системный блок.
4. **Кэш браузера**
   - выполнить жесткое обновление страницы (`Ctrl+F5`);
   - при необходимости очистить кэш браузера и перезапустить страницу.
5. **Логи браузера**
   - в `Console` проверить ошибки `fetch`/`HTTP` по вызовам `user-primary-location` и `system-blocks`.
6. **Права доступа**
   - функционал доступен в контроллере для авторизованных администраторов.

## 8. Минимальный сценарий проверки (быстрый smoke test)

1. Открыть `Учет ТС`.
2. Выбрать 1-2 записи с назначенным ответственным и помещением.
3. Нажать `Переместить/Переназначить`.
4. В режиме `Обычное переназначение` выбрать другого пользователя.
5. Проверить, что `Помещение` изменилось автоматически (если для пользователя найдено основное помещение).
6. Убедиться, что кнопка `Сохранить` стала активной.
7. Сохранить и проверить факт изменения в таблице после обновления.

## 9. Примечание по сопровождению

При изменении имен полей модального окна или URL серверных методов документ должен быть обновлен синхронно с кодом.
