# Анализ текущего состояния ИАС учёта технических средств

Документ подготовлен по состоянию репозитория и кода приложения. Цель — зафиксировать, что реализовано, что осталось сделать и какие изменения целесообразно внести.

**Дата актуализации:** с учётом выполненных работ по документу docs/planning/26_02_26_ЧТО_НЕ_РЕАЛИЗОВАНО_И_ПЛАН_ДЕЙСТВИЙ.md (реализованы разделы 2.2–2.5 без п. 2.1 — нулевая волна).

## 1. Существование системы: общая оценка

Система **существует** в виде рабочего прототипа на стеке PHP (Yii2) + PostgreSQL с веб-интерфейсом (AG Grid). Реализованы ядро Help Desk, учёт активов (оборудования), управление пользователями, частично — вложения, справочники, отчётность, аудит и контур «ПО и лицензии». Документация (ТЗ, модель БД, план реализации, требования) приведена в порядок и привязана к ВКР и эксплуатации.

**Вывод:** система находится в стадии активной разработки и доработки; до промышленной эксплуатации необходимо закрыть пробелы по безопасности, правам доступа, импорту данных и ряду функциональных контуров.

## 6. Заключение

Система существует как работоспособный прототип с развитой документацией. По состоянию на актуализацию документа выполнены: первая волна (права на заявки, аудит входа/выхода), связь заявка–актив, нормализация вложений (task_attachments), проверки прав на вложения и get-user-equipment, импорт из «Основной Учет.xlsx» (скрипт + консольная команда), универсальный импорт (CSV/JSON/XML/XLSX), отчёт по истекающим лицензиям, документация этапа 1 (роль оператор, AG Grid, схема импорта, API) и документы этапов 4–7 (регламент миграции, программа испытаний, руководства, ввод в эксплуатацию).

Остаётся по решению: нулевая волна (замена MD5 на bcrypt, ограничение тестовых экшенов) — при необходимости выполнить без нарушения текущей работы. Далее целесообразны проведение испытаний по программе и методике и подготовка к вводу в эксплуатацию. Рекомендации по унификации API и UX, очистке репозитория и ВКР сохраняют актуальность.
