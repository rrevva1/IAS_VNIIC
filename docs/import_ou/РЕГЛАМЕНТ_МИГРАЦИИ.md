# Регламент миграции данных (Этап 4)

Документ фиксирует порядок миграции данных в систему учёта ТС и контрольные сверки после импорта.

## Источники данных

- Файл «Основной Учет.xlsx» (листы АРМ, Принтеры) — первичное наполнение оборудования, локаций, пользователей, характеристик (part_char_values).
- Универсальный импорт (CSV, JSON, XML, XLSX) — пополнение оборудования по согласованному маппингу полей (см. [УНИВЕРСАЛЬНЫЙ_ИМПОРТ.md](УНИВЕРСАЛЬНЫЙ_ИМПОРТ.md)).
- Ручной ввод и операции в системе — заявки, вложения, учёт ПО и лицензий.

## Целевая схема

БД **ias_vniic**, схема **tech_accounting**. DDL и порядок создания объектов — в `scripts/create_ias_vniic.sql`. Перед миграцией выполнить создание БД и применение скрипта (см. комментарии в начале скрипта).

## Порядок миграции

1. Создать БД и применить `scripts/create_ias_vniic.sql`.
2. При необходимости выполнить начальное наполнение справочников (уже входит в скрипт: roles, dic_task_status, dic_equipment_status и т.д.).
3. Импорт из «Основной Учет.xlsx»: выполнить `python3 scripts/load_ou_main.py` или `php yii import-ou` из каталога приложения; зафиксировать протокол (количество обработанных строк, ошибки).
4. При наличии legacy-данных (вложения в JSON, старые таблицы) — выполнить одноразовые скрипты миграции по регламенту из [ОПИСАНИЕ_И_ПЛАН_ДЕЙСТВИЙ_БД_ias_vniic.md](../bd/ОПИСАНИЕ_И_ПЛАН_ДЕЙСТВИЙ_БД_ias_vniic.md) (раздел 2.4).
5. Создать первого пользователя-администратора (вручную или скриптом, например `scripts/create-initial-admin.php` при наличии).

## Контрольные сверки после импорта

- Сравнить количество записей в таблице `equipment` с ожидаемым по источнику (лист АРМ + Принтеры).
- Проверить наличие записей в `locations`, `users`, `part_char_values` в соответствии с источником.
- Проверить отсутствие дубликатов по уникальным полям (`inventory_number`, при необходимости `serial_number`).
- Выборочно проверить корректность маппинга полей (ответственный, помещение, тип техники) по нескольким записям.
- При повторном запуске импорта (идемпотентность) убедиться, что данные не дублируются и обновляются по ключу (inventory_number).

Критерий успешности: протокол импорта без критических ошибок; количество записей в целевых таблицах соответствует ожиданию; выборочная проверка данных подтверждает корректность.

## Резервное копирование

Перед массовым импортом выполнить резервную копию БД (pg_dump). После миграции сохранить дамп для возможности отката.
