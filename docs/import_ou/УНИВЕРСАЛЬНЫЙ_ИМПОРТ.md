# Универсальный импорт (ТЗ 5.1.11)

Импорт данных в систему по согласованным форматам с формированием протокола (обработано / ошибки).

## Форматы и кодировка

- **CSV** — разделитель «;» или «,», первая строка — заголовки. Кодировка UTF-8 (при необходимости конвертация из Windows-1251 выполняется автоматически).
- **JSON** — массив объектов либо объект с ключом `items` (массив). Каждый элемент — объект с полями по маппингу сущности.
- **XML** — корневой элемент содержит дочерние элементы `item`, `row`, `equipment` или `record`; у каждого дочернего — теги с именами полей.
- **XLSX** — первый лист; первая строка — заголовки, далее строки данных.

## Сущность: оборудование (equipment)

Ожидаемые поля в каждой строке/записи:

| Поле в файле   | Обязательное | Описание |
|----------------|--------------|----------|
| inventory_number или inv | Нет* | Инв. номер. При пустом — генерируется. При совпадении с существующим — обновление записи. |
| name            | Нет* | Наименование. При пустом — равно инв. номеру. Макс. 200 символов. |
| location или location_name | Да | Название помещения (кабинет). При отсутствии в БД создаётся новая локация типа «кабинет». |
| description     | Нет | Описание. |
| status_id       | Нет | ID статуса оборудования. При отсутствии — статус по умолчанию (в эксплуатации). |

\* Хотя бы одно из полей inventory_number/inv или name должно быть непустым.

## Валидация

- Даты (если передаются): не ранее 01.01.2000 (по проектному решению).
- Длина строковых полей: inventory_number — до 100, name — до 200 символов.
- Помещение обязательно; при отсутствии — запись пропускается с сообщением в протоколе.

## Протокол импорта

После загрузки отображаются:
- количество успешно обработанных записей;
- количество ошибок;
- перечень сообщений об ошибках (строка, причина).

## Доступ

Универсальный импорт доступен только пользователям с ролью **администратор** (раздел «Импорт» в меню).
