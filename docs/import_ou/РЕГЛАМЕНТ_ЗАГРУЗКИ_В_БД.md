# Регламент загрузки данных в БД

Документ фиксирует полный порядок загрузки данных из файлов учета в БД `ias_vniic` (схема `tech_accounting`).

Регламент обязателен для чистовой загрузки после очистки БД и для повторных прогонов импорта.

---

## 1. Обязательный комплект документов

Перед загрузкой должны быть актуальны следующие документы:

1. `docs/import_ou/РЕГЛАМЕНТ_ПАРСИНГА.md`  
   Единый источник правил парсинга столбцов, неатомарных значений, синтетических номеров и маппинга по листам.
2. `docs/bd/МАППИНГ_КОЛОНОК_УЧЕТ_ТС.md`  
   Маппинг колонок представления «Учет ТС» на таблицы БД.
3. `docs/bd/СТРУКТУРА_ЛИСТА_АРМ_ОСНОВНОЙ_УЧЕТ.md`  
   Фактическая структура листов источника.
4. `scripts/create_ias_vniic.sql`  
   Эталон DDL целевой БД.

---

## 2. Источники загрузки

### 2.1. Приоритетные листы

- `Основной Учет.xlsx` → лист `АРМ` (ядро активов АРМ).
- `Основной Учет.xlsx` → лист `Принтеры` (активы типа `Принтер`/`МФУ`).

### 2.2. Листы второго контура

- `Поставки 2017-2019` ... `Поставки 2025` — используются для обогащения поставщиком/датами.
- `СБ забрали`, `Принтеры забрали`, `Мониторы забрали` — загружаются только отдельным архивным этапом, не в основной активный контур.

---

## 3. Предзагрузочная проверка

Перед запуском импорта необходимо:

1. Проверить, что БД создана и доступна: `ias_vniic`, `tech_accounting`.
2. Проверить наличие справочников и статусов:
   - `dic_equipment_status`
   - `spr_parts`
   - `spr_chars`
3. Проверить, что в таблице `equipment` действует уникальность `inventory_number`.
4. Проверить, что в `part_char_values` действует ограничение уникальности `(equipment_id, part_id, char_id)` и учесть это в формате записи множественных значений.
5. Проверить путь к исходному Excel:
   - по умолчанию файл в корне проекта;
   - либо задать `OU_MAIN_EXCEL`.

---

## 4. Порядок загрузки в БД

Загрузка выполняется строго в следующей последовательности:

1. Справочники (`dic_equipment_status`, `spr_parts`, `spr_chars`, при необходимости типы техники).
2. Пользователи (`users`) из колонок `Пользователь`.
3. Помещения (`locations`) из колонок `Помещение`.
4. Основные активы по листу `АРМ`:
   - системные блоки,
   - ноутбуки,
   - моноблоки.
5. Дочерние активы по `АРМ`:
   - мониторы (отдельные записи `equipment`),
   - ИБП (отдельные записи `equipment`).
6. Активы по листу `Принтеры`:
   - `Принтер`,
   - `МФУ`.
7. Связи компонентов (`equipment_links`):
   - системный блок → монитор,
   - системный блок → ИБП.
8. Характеристики (`part_char_values`):
   - ЦП, ОЗУ, диск, ОС, IP, имя ПК, антивирус,
   - исходные учетные признаки для повторяющихся инвентарных значений.
9. История (`equip_history`) при необходимости сценария.
10. Протокол импорта:
    - для web-контура (контроллеры приложения) — `equipment_import_logs` и/или таблицы протокола, реализованные в приложении;
    - для Python-скриптов (`load_ou_main.py`, `load_ou_test_20rows.py`) — протокол в stdout/файл запуска, если запись в таблицы протокола не реализована.

---

## 5. Правила качества данных

### 5.1. Уникальность инвентарных номеров

Повторяющиеся учетные признаки (`МЦ.04`, `НИИСУ`, `Электроника`, `99036` и подобные) не загружать как уникальный `equipment.inventory_number` для разных активов.

Использовать внутренние номера:

- `МЦ.04-pc-XXX`
- `МЦ.04-mon-XXX`
- `МЦ.04-ups-XXX`
- `МЦ.04-prn-XXX`

Исходное значение сохранять в `description` или `part_char_values`.

### 5.2. Неатомарные значения

- Базовый разделитель: `\n`.
- Для `Диск` в полном файле также разделять по запятой.
- Для `Монитор` допускается `; `.

### 5.3. Ограничение `part_char_values`

До изменения схемы множественные однотипные характеристики одного актива хранить объединенно в `value_text` (перенос строки), если они конфликтуют с уникальностью `(equipment_id, part_id, char_id)`.

---

## 6. Минимальный контроль после загрузки

После завершения импорта выполнить контроль:

1. Количество загруженных активов по типам:
   - `Системный блок`/`Ноутбук`/`Моноблок`
   - `Монитор`
   - `ИБП`
   - `Принтер`/`МФУ`
2. Отсутствие дубликатов `equipment.inventory_number`.
3. Отсутствие осиротевших ссылок:
   - `equipment.responsible_user_id`
   - `equipment.location_id`
   - `equipment_links.parent_equipment_id` / `child_equipment_id`
4. Проверка заполнения характеристик по обязательным колонкам.
5. Наличие протокола запуска:
   - запись в таблице протокола (если импорт запускался через web-контур),
   - либо сохраненный вывод Python-скрипта/лог-файл запуска (если запускался CLI-скрипт).

## 7. Команды запуска

### 7.1. Основная загрузка

```bash
python3 scripts/load_ou_main.py
```

### 7.2. Тестовый прогон на первых строках

```bash
python3 scripts/load_ou_test_20rows.py
```

---

## 8. Критерии готовности к эксплуатации

Загрузка считается корректной, если:

1. Выполнен порядок из раздела 4.
2. Выполнены проверки раздела 6.
3. Нет блокирующих ошибок в протоколе импорта.
4. Маппинг данных соответствует `РЕГЛАМЕНТ_ПАРСИНГА.md`.
5. Результат подтвержден ответственным за данные.
