# Регламент парсинга Основного учета

Единый документ правил парсинга файлов `ОУ_тест.xlsx`, **`ОУ.xlsx`** и `Основной Учет.xlsx` при загрузке в БД. `ОУ_тест.xlsx` и `ОУ.xlsx` используются как укороченные контрольные/рабочие выгрузки формата листа «АРМ»; для полного наполнения предприятия основным источником является `Основной Учет.xlsx`. Правила столбцов и числа физических мониторов **одинаковы** для всех перечисленных файлов.

Все решения по листам, столбцам, особым значениям и неоднозначностям фиксируются здесь. Скрипт загрузки и описание примеров должны следовать этому регламенту.

---

## 1. Общие правила

| Правило | Описание |
|---------|----------|
| **Источники чистовой загрузки** | В первую очередь загружаются листы **АРМ** и **Принтеры** полного файла `Основной Учет.xlsx`. Листы **Поставки 2017-2019 ... 2025** используются вторым проходом для уточнения поставщика и дат, но не как основной источник создания активов. Листы **СБ забрали**, **Принтеры забрали**, **Мониторы забрали** не смешиваются с текущим активным учетом и загружаются только отдельным архивным этапом. |
| **Разделитель неатомарных ячеек** | Базовый разделитель — перенос строки (`\n`). Для столбца **Диск** в полном файле дополнительно используется запятая как разделитель накопителей. Для **ЦП** запятая не является разделителем, например «3,3 ГГц» хранится целиком. Для **Монитор** допускается `; ` как разделитель нескольких физических мониторов. |
| **Помещение** | Число (103, 105) приводить к строке для `locations.name`: `"103"`, `"105"`. |
| **Пустые ячейки** | Не заполняем целевые поля (NULL / пропуск записи в part_char_values). |
| **Семантика строки** | Одна строка листа АРМ даёт **одну запись equipment** на ПК/ноутбук/моноблок, если в строке есть признаки ПК; **плюс** по п. 1.1 — отдельные записи equipment на каждый монитор из столбца «Монитор» и на каждый ИБП из столбца «Другая техника». Строка «только монитор» создаёт одну или несколько записей equipment типа «Монитор». |
| **Уникальность inventory_number в БД** | Поле `equipment.inventory_number` в системе **обязательно уникально** — это ключ записи актива. Значение в Excel **не всегда** является уникальным идентификатором физической единицы (см. п. 1.2.1). Повторяющиеся учётные пометки (`МЦ.04`, `МЦ.04.1`, `НИИСУ` и т.п.) **нельзя** назначать разным активам как единый `inventory_number` без внутренней нумерации по п. 1.2. |
| **Оргтехника и комплект АРМ** | Принтеры, МФУ и сканеры — **самостоятельные** записи `equipment`. **Не** создаются связи `equipment_links` с ПК; **не** загружаются характеристики комплекта АРМ (ЦП, ОЗУ, монитор, имя ПК, ОС и т.д.) — только допустимые поля листа «Принтеры» (п. 4). |
| **«Другая техника»** | Столбец листа **АРМ** «Другая техника» (в UI — «ДР техника») относится **только** к строке-ПК/хосту. У записей типа **Монитор**, **ИБП**, **Принтер**, **МФУ**, **Сканер** поле **не заполняется** и в интерфейсе **не отображается** (п. 1.5). |
| **Ссылка на регламент** | При реализации парсера/загрузчика использовать **только** этот документ как источник правил по столбцам и особым значениям. |

### 1.1. Разнесение мониторов и ИБП: одна запись equipment = один физический актив

В системе принят принцип **одна запись в таблице equipment = одна физическая единица техники** (см. `docs/sistema/УТОЧНЕНИЕ_УЧЕТ_МОНИТОРЫ_ИБП_МЦ04.md`). При парсинге листа АРМ это означает:

| Объект | В источнике (ячейка) | В БД после загрузки |
|--------|----------------------|----------------------|
| **Мониторы** | Столбец «Монитор»: одно значение или несколько через `\n`, `; ` (например «AOC 24P2Q; AOC 24P2Q», «Philips 23.8" 241B8QJEB\nPhilips 23.8" 241B8QJEB»). | На каждую **физическую единицу** создаётся **отдельная запись equipment** с equipment_type = «Монитор», тем же responsible_user_id и location_id, что у строки-ПК. Наименование (equipment.name) — модель этого монитора. Инв. номер — синтетический **МЦ.04-mon-XXX** (мониторы учёт МЦ.04, инв. номера в бухгалтерии не присваиваются). Для строки-ПК в **part_char_values** по-прежнему можно сохранить конфигурацию (тип части «Монитор», значение — модель/модели для справки). |
| **ИБП** | Столбец «Другая техника»: текст вида «ИБП &lt;марка и модель&gt;» (например «ИБП APC Back-UPS 650 ВА (BX650CI-RS)», «ИБП Powercom RPT-1000A EURO»). В одной ячейке может быть один ИБП или несколько через `\n`. | На каждый ИБП создаётся **отдельная запись equipment** с equipment_type = «ИБП», тем же responsible_user_id и location_id, что у строки-ПК. equipment.name = текст после «ИБП » (марка и модель). Инв. номер — синтетический **МЦ.04-ups-XXX**. В **equipment.description** строки-ПК переносить ИБП **не** оставляем (после извлечения поле очищается или в него не пишем эти подстроки). |

**Итог для парсера:**

- **Столбец «Монитор»:** разбить значение по разделителям (`\n`, при необходимости `; `); для каждой подстроки (модель монитора) создать запись equipment (тип «Монитор», name = подстрока, inventory_number = МЦ.04-mon-001, …); для строки-ПК при необходимости заполнить part_char_values (Монитор) — по одному или несколько значений для отображения конфигурации в гриде.
- **Столбец «Другая техника»:** найти подстроки с ИБП: явный префикс «ИБП » или известные модели/производители (`APC Back-UPS`, `Powercom`, `Ippon`, `SVEN`, `CyberPower`, `DCM` и т.п.); для каждой подтверждённой подстроки создать запись equipment (тип «ИБП», name = марка/модель, inventory_number = МЦ.04-ups-001, …); в description записи ПК не класть извлечённые ИБП.
- **Столбцы 19–21 (ведомость бух. инвентаризации МЦ):** **не** увеличивают число записей equipment типа «Монитор» и **не** создают связи `equipment_links`. Значения вроде `МЦ.04.1` в колонке «Монитор в ведомости бух.» при одной модели в столбце «Монитор» — учётная пометка, а не вторая физическая единица (см. п. 1.1.1).

Нумерация МЦ.04-mon-XXX и МЦ.04-ups-XXX — сквозная в рамках одного запуска загрузки (или по регламенту генерации уникальных номеров).

#### 1.1.1. Алгоритм числа мониторов (`monitor_kit_entries`)

Применяется в `scripts/load_ou_main.py` и `scripts/link_ou_kits_only.py` (см. `РЕГЛАМЕНТ_ЗАГРУЗКИ_В_БД.md`, п. 5.1.5).

| Шаг | Правило |
|-----|---------|
| 1 | Взять список моделей: `monitor_parts` («Монитор»). |
| 2 | Если моделей **две и более** — столько же активов-мониторов (сопоставление с «№ монитора» по порядку, если в ячейке несколько **реальных** номеров). |
| 3 | Если модель **одна**, а в «№ монитора» через `\n` несколько **реальных** (не `НИИСУ`, не голый `МЦ.04`) номеров — столько же активов с той же моделью. |
| 4 | Иначе — **один** актив-монитор на строку-ПК. |
| 5 | Колонка «Монитор в ведомости бух.» (19–20) **не** участвует в шагах 1–4. |

Повторяющиеся учётные пометки для целей п. 3–4: `НИИСУ`, `МЦ.04` (без суффикса), `Электроника`, `99036`, `?`, `МОЛ` (полный перечень — п. 1.2 и `РЕГЛАМЕНТ_ЗАГРУЗКИ_В_БД.md`, п. 6.1).

### 1.2. Правило формирования уникальных инвентарных номеров

В БД `equipment.inventory_number` является обязательным и **уникальным** полем. В файле учёта в том же столбце часто указывается **не** инвентарный номер конкретной единицы, а **учётный признак бухгалтерии** (см. п. 1.2.1). Загрузчик обязан обеспечить уникальность в БД, сохранив исходное значение для сверки с ведомостью.

| Ситуация | Действие |
|----------|----------|
| В ячейке указан очевидный уникальный инвентарный номер (`00-000804`, `190354`, `19099` и т.п.) — не встречается у других физических активов в том же файле и не совпадает с записью **другого типа** техники в БД | Использовать значение как `equipment.inventory_number` (при повторном прогоне — обновление той же записи по этому ключу). |
| В ячейке указан общий учётный признак или повторяющееся значение (`МЦ.04`, `МЦ.04.1`, `МЦ.04.2`, `НИИСУ`, `Электроника`, `99036`, `?`, МОЛ и т.п.) | Создать **внутренний** уникальный номер по типу актива: `МЦ.04-pc-XXX`, `МЦ.04-mon-XXX`, `МЦ.04-ups-XXX`, `МЦ.04-prn-XXX` (в `load_ou_main.py` также `МЦ.04-принтер-{N}`). Исходное значение сохранить в `equipment.description` и/или `part_char_values` («Исходный учётный номер»). |
| Инвентарный номер отсутствует | Создать внутренний уникальный номер по типу актива и записать отсутствие исходного номера в лог импорта. |
| В ячейке несколько строк | Для основного ПК брать первую строку как исходное значение; остальные строки сохранять в описание/характеристику. Для нескольких мониторов формировать отдельные внутренние номера на каждую физическую единицу. |
| В БД уже есть актив **другого класса** с тем же значением в `inventory_number` (коллизия ПК ↔ принтер/МФУ/сканер) | **Не перезаписывать** существующую запись. Для новой строки источника сформировать отдельный внутренний номер: `{исходное}-оргтехника-{N}` или `{исходное}-строка{N}` (см. п. 1.2.2). |

Внутренний номер должен быть стабилен в рамках одного чистового прогона. Рекомендуется вести счётчик по типам активов и фиксировать соответствие «строка Excel → созданный `inventory_number`» в протоколе импорта.

#### 1.2.1. Учётная практика предприятия (неуникальные значения в источнике)

На предприятии части технических средств **не получают отдельный инвентарный номер в бухгалтерии**. Учёт ведётся **по одной бухгалтерской ведомости** (группа основных средств МЦ, в файле — пометки `МЦ.04`, `МЦ.04.1`, `МЦ.04.2` и аналоги). Одно и то же значение в столбце «Инвент. №» / «№ системн. блока» / «№ монитора» / «Инвент. № принтера» означает:

| В источнике | Смысл для импорта |
|-------------|-------------------|
| Одинаковое значение у **разных строк** одного листа | Разные физические единицы с **общим бухучётным признаком**, а не дубликат одной записи. |
| Одинаковое значение у **разных листов** (АРМ и Принтеры) или у активов **разного типа** | Разные объекты учёта (ПК, монитор, принтер, сканер), проходящие по **одной ведомости**; в БД им **нельзя** назначать один `inventory_number`. |
| Столбцы «… в ведомости бух. инвентаризации МЦ» | Справочная пометка о включении в ведомость; **не** увеличивает число физических активов (п. 1.1.1, п. 3). |

**Вывод для парсера:** значение из Excel трактуется как **исходный учётный номер / признак ведомости**; уникальный `equipment.inventory_number` в системе назначается по п. 1.2. Исходное значение **обязательно сохраняется** в `description` или характеристике для сверки с бухгалтерией и инвентаризацией.

#### 1.2.2. Коллизии при повторной загрузке и смешанных типах техники

При импорте листа **Принтеры** (и выгрузок «Принтеры / МФУ / Сканеры» того же формата) действуют дополнительные ограничения:

| Правило | Описание |
|---------|----------|
| **Запрет перезаписи ПК** | Если в БД уже существует запись с данным `inventory_number` и типом из класса **хост/комплект АРМ** (`АРМ`, `ПК`, `Системный блок`, `Ноутбук`, `Моноблок`, `Монитор`, `ИБП` и т.п.), импорт оргтехники **не обновляет** эту запись. Создаётся **новая** запись с внутренним номером (`{исходный}-оргтехника-{номер_строки}` и др.). |
| **Очистка «наследия» комплекта** | После создания/обновления записи оргтехники удаляются характеристики ПК (`part_char_values` с типами частей ЦП, ОЗУ, Монитор, ПК и т.д.) и все связи `equipment_links` с этой записью. Допускается только характеристика **«Принтер» → «IP адрес»** (или USB), если указана в источнике. |
| **Без связи с ПК** | Принтеры, МФУ и сканеры **не** включаются в комплект АРМ: не создаются и не сохраняются связи `equipment_links` с родителем-ПК. |
| **Идемпотентность** | Повторный прогон по тому же внутреннему `inventory_number` обновляет **ту же** запись оргтехники (наименование, помещение, ответственный, IP), не затрагивая записи ПК с исходным бухучётным признаком. |

Реализация в `scripts/load_ou_main.py`: функции `resolve_org_inventory`, `reset_org_equipment_side_effects` (см. `РЕГЛАМЕНТ_ЗАГРУЗКИ_В_БД.md`, п. 6.1).

### 1.5. Столбец «Другая техника» (только хост АРМ)

| Тип `equipment` | «Другая техника» / `equipment.description` как ДР техника |
|---------------|-----------------------------------------------------------|
| **АРМ**, **ПК**, **Системный блок**, **Ноутбук**, **Моноблок** | Да: остаток ячейки «Другая техника» после извлечения подстрок «ИБП …» (отдельные записи equipment) + при необходимости «Примечание» строки-ПК. |
| **Монитор** | **Нет.** Допускается только служебная пометка «Исходный учётный номер: …» при создании актива-монитора, **не** как «Другая техника». |
| **ИБП** | **Нет** (`description` пустое, если иное не задано отдельным регламентом). |
| **Принтер**, **МФУ**, **Сканер** | **Нет** содержимого столбца АРМ «Другая техника». Примечания листа «Принтеры» хранятся в `description` для справки, в колонке «ДР техника» грида **не выводятся**. |

ИБП из ячейки «Другая техника» **всегда** выносятся в отдельные записи `equipment` (п. 1.1); у родительского ПК в «ДР техника» остаётся только **прочий** текст после извлечения ИБП.

### 1.3. Порядок загрузки после очистки БД

После очистки БД данные загружаются в следующей последовательности:

1. Заполнить справочники `dic_equipment_status`, `spr_parts`, `spr_chars` и при необходимости справочник типов техники.
2. Создать/найти пользователей из колонок `Пользователь`.
3. Создать/найти помещения из колонок `Помещение`.
4. Создать основные записи `equipment` по листу **АРМ**: системные блоки, ноутбуки, моноблоки.
5. Создать дочерние активы `equipment`: мониторы и ИБП из листа **АРМ**.
6. Создать записи `equipment` по листу **Принтеры**.
7. Создать связи `equipment_links`: системный блок → монитор, системный блок → ИБП; диски связывать отдельными активами только при принятом решении, иначе хранить как характеристики.
8. Заполнить `part_char_values` характеристиками: ЦП, ОЗУ, диск, ОС, IP адрес, имя ПК, антивирус, исходные учетные номера и служебные признаки, разрешенные регламентом.
9. Записать события создания/архивации в `equip_history`, если это требуется сценарием загрузки.
10. Зафиксировать результат в `import_runs` / `import_errors` или `equipment_import_logs`.

### 1.4. Ограничение `part_char_values`

В текущей схеме для `part_char_values` действует уникальность по набору `equipment_id + part_id + char_id`. Поэтому несколько одинаковых характеристик одного типа для одного оборудования нельзя без изменения схемы записывать отдельными строками с одинаковыми `part_id` и `char_id`.

До изменения схемы применяется правило:

- для дисков, IP-адресов, номеров мониторов и дат мониторов допускается хранить несколько значений в одной записи `value_text`, разделяя их переносом строки;
- отдельные физические мониторы и ИБП должны храниться не как повторяющиеся характеристики, а как отдельные записи `equipment`;
- если требуется строго хранить несколько дисков отдельными строками, необходимо предварительно изменить модель характеристик: добавить порядковый номер/экземпляр компонента или отдельную таблицу компонентов.

Для каждого столбца указаны: смысл значения, куда грузить, особые значения, примечания и нерешённые вопросы.

### Столбец 1 — Пользователь

| Параметр | Значение |
|----------|----------|
| **Смысл** | ФИО ответственного (закреплённое за оборудованием лицо). |

| Параметр | Правило |
|----------|---------|
| **Тип** | «Принтер», «МФУ» (по тексту оргтехники) или «Сканер» (если в наименовании есть «сканер»). |

## 6. Открытые вопросы и решения

Вносить сюда пункты, по которым решение ещё не принято; после принятия — переносить в п. 2 и сводную таблицу.

| Вопрос | Текущее состояние | Ответственный |
|--------|-------------------|---------------|
| Куда хранить статус «Карточка оформлена» (подписана ли карточка на оборудовании)? | Не загружаем; поле users.department не использовать для этого значения. | Уточнить с заказчиком: отдельное поле equipment, справочник, описание. |
| Будет ли в схеме поле department у пользователя и откуда его заполнять? | Не определено. | Уточнить с заказчиком. |
| «Другая техника» (ИБП и т.д.) — только description или отдельные записи equipment? | **Решено:** ИБП — отдельные записи equipment (тип «ИБП», name = марка и модель после «ИБП », inv. МЦ.04-ups-XXX). См. п. 1.1 и столбец 18. | Зафиксировано в п. 1.1, столбцы 11 и 18. |
| Как хранить несколько однотипных характеристик в `part_char_values`? | До изменения схемы — одним `value_text` со списком; физические мониторы и ИБП — отдельными `equipment`. | Если потребуется несколько дисков как отдельные строки, доработать схему характеристик. |
| Как грузить повторяющиеся инвентарные признаки МЦ.04/НИИСУ/99036? | Как исходные учетные признаки, не как уникальные `equipment.inventory_number`. | Внутренний уникальный номер по п. 1.2. |
