# Регламент парсинга Основного учета

Единый документ правил парсинга файлов `ОУ_тест.xlsx` и `Основной Учет.xlsx` при загрузке в БД. `ОУ_тест.xlsx` используется как укороченный контрольный пример формата листа «АРМ»; для чистовой загрузки после очистки БД основным источником является полный файл `Основной Учет.xlsx`.

Все решения по листам, столбцам, особым значениям и неоднозначностям фиксируются здесь. Скрипт загрузки и описание примеров должны следовать этому регламенту.

---

## 1. Общие правила

| Правило | Описание |
|---------|----------|
| **Источники чистовой загрузки** | В первую очередь загружаются листы **АРМ** и **Принтеры** полного файла `Основной Учет.xlsx`. Листы **Поставки 2017-2019 ... 2025** используются вторым проходом для уточнения поставщика и дат, но не как основной источник создания активов. Листы **СБ забрали**, **Принтеры забрали**, **Мониторы забрали** не смешиваются с текущим активным учетом и загружаются только отдельным архивным этапом. |
| **Разделитель неатомарных ячеек** | Базовый разделитель — перенос строки (`\n`). Для столбца **Диск** в полном файле дополнительно используется запятая как разделитель накопителей. Для **ЦП** запятая не является разделителем, например «3,3 ГГц» хранится целиком. Для **Монитор** допускается `; ` как разделитель нескольких физических мониторов. |
| **Помещение** | Число (103, 105) приводить к строке для `locations.name`: `"103"`, `"105"`. |
| **Пустые ячейки** | Не заполняем целевые поля (NULL / пропуск записи в part_char_values). |
| **Семантика строки** | Одна строка листа АРМ даёт **одну запись equipment** на ПК/ноутбук/моноблок, если в строке есть признаки ПК; **плюс** по п. 1.1 — отдельные записи equipment на каждый монитор из столбца «Монитор» и на каждый ИБП из столбца «Другая техника». Строка «только монитор» создаёт одну или несколько записей equipment типа «Монитор». |
| **Уникальность inventory_number** | Поле `equipment.inventory_number` уникально. Значения вида «МЦ.04», «МЦ.04.1», «МЦ.04.2», «НИИСУ», «Электроника», «99036» и другие повторяющиеся учетные пометки **нельзя** массово грузить как реальные уникальные инвентарные номера разных активов. Для таких активов формируется внутренний уникальный номер по п. 1.2, а исходное значение сохраняется в `description` или характеристике. |
| **Ссылка на регламент** | При реализации парсера/загрузчика использовать **только** этот документ как источник правил по столбцам и особым значениям. |

### 1.1. Разнесение мониторов и ИБП: одна запись equipment = один физический актив

В системе принят принцип **одна запись в таблице equipment = одна физическая единица техники** (см. `docs/sistema/УТОЧНЕНИЕ_УЧЕТ_МОНИТОРЫ_ИБП_МЦ04.md`). При парсинге листа АРМ это означает:

| Объект | В источнике (ячейка) | В БД после загрузки |
|--------|----------------------|----------------------|
| **Мониторы** | Столбец «Монитор»: одно значение или несколько через `\n`, `; ` (например «AOC 24P2Q; AOC 24P2Q», «Philips 23.8" 241B8QJEB\nPhilips 23.8" 241B8QJEB»). | На каждую **физическую единицу** создаётся **отдельная запись equipment** с equipment_type = «Монитор», тем же responsible_user_id и location_id, что у строки-ПК. Наименование (equipment.name) — модель этого монитора. Инв. номер — синтетический **МЦ.04-mon-XXX** (мониторы учёт МЦ.04, инв. номера в бухгалтерии не присваиваются). Для строки-ПК в **part_char_values** по-прежнему можно сохранить конфигурацию (тип части «Монитор», значение — модель/модели для справки). |
| **ИБП** | Столбец «Другая техника»: текст вида «ИБП &lt;марка и модель&gt;» (например «ИБП APC Back-UPS 650 ВА (BX650CI-RS)», «ИБП Powercom RPT-1000A EURO»). В одной ячейке может быть один ИБП или несколько через `\n`. | На каждый ИБП создаётся **отдельная запись equipment** с equipment_type = «ИБП», тем же responsible_user_id и location_id, что у строки-ПК. equipment.name = текст после «ИБП » (марка и модель). Инв. номер — синтетический **МЦ.04-ups-XXX**. В **equipment.description** строки-ПК переносить ИБП **не** оставляем (после извлечения поле очищается или в него не пишем эти подстроки). |

**Итог для парсера:**

- **Столбец «Монитор»:** разбить значение по разделителям (`\n`, при необходимости `; `); для каждой подстроки (модель монитора) создать запись equipment (тип «Монитор», name = подстрока, inventory_number = МЦ.04-mon-001, …); для строки-ПК при необходимости заполнить part_char_values (Монитор) — по одному или несколько значений для отображения конфигурации в гриде.
- **Столбец «Другая техника»:** найти подстроки с ИБП: явный префикс «ИБП » или известные модели/производители (`APC Back-UPS`, `Powercom`, `Ippon`, `SVEN`, `CyberPower`, `DCM` и т.п.); для каждой подтверждённой подстроки создать запись equipment (тип «ИБП», name = марка/модель, inventory_number = МЦ.04-ups-001, …); в description записи ПК не класть извлечённые ИБП.

Нумерация МЦ.04-mon-XXX и МЦ.04-ups-XXX — сквозная в рамках одного запуска загрузки (или по регламенту генерации уникальных номеров).

### 1.2. Правило формирования уникальных инвентарных номеров

В БД `equipment.inventory_number` является обязательным и уникальным полем. При чистовой загрузке применяется следующий порядок:

| Ситуация | Действие |
|----------|----------|
| В ячейке указан очевидный уникальный инвентарный номер (`00-000804`, `190354` и т.п.) | Использовать значение как `equipment.inventory_number`. |
| В ячейке указан общий учетный признак или повторяющееся значение (`МЦ.04`, `МЦ.04.1`, `МЦ.04.2`, `НИИСУ`, `Электроника`, `99036`, `?`, МОЛ и т.п.) | Создать внутренний уникальный номер по типу актива: `МЦ.04-pc-XXX`, `МЦ.04-mon-XXX`, `МЦ.04-ups-XXX`, `МЦ.04-prn-XXX`. Исходное значение сохранить в `equipment.description` или `part_char_values` как «Исходный учетный номер». |
| Инвентарный номер отсутствует | Создать внутренний уникальный номер по типу актива и записать отсутствие исходного номера в лог импорта. |
| В ячейке несколько строк | Для основного ПК брать первую строку как исходное значение; остальные строки сохранять в описание/характеристику. Для нескольких мониторов формировать отдельные внутренние номера на каждую физическую единицу. |

Внутренний номер должен быть стабилен в рамках одного чистового прогона. Рекомендуется вести счетчик по типам активов и фиксировать соответствие «строка Excel → созданный inventory_number» в протоколе импорта.

### 1.3. Порядок загрузки после очистки БД

После очистки БД данные загружаются в следующей последовательности:

1. Заполнить справочники `dic_equipment_status`, `spr_parts`, `spr_chars` и при необходимости справочник типов техники.
2. Создать/найти пользователей из колонок `Пользователь`.
3. Создать/найти помещения из колонок `Помещение`.
4. Создать основные записи `equipment` по листу **АРМ**: системные блоки, ноутбуки, моноблоки.
5. Создать дочерние активы `equipment`: мониторы и ИБП из листа **АРМ**.
6. Создать записи `equipment` по листу **Принтеры**.
7. Создать связи `equipment_links`: системный блок → монитор, системный блок → ИБП; диски связывать отдельными активами только при принятом решении, иначе хранить как характеристики.
8. Заполнить `part_char_values` характеристиками: ЦП, ОЗУ, диск, ОС, IP адрес, имя ПК, антивирус, исходные учетные номера и служебные признаки, разрешенные регламентом.
9. Записать события создания/архивации в `equip_history`, если это требуется сценарием загрузки.
10. Зафиксировать результат в `import_runs` / `import_errors` или `equipment_import_logs`.

### 1.4. Ограничение `part_char_values`

В текущей схеме для `part_char_values` действует уникальность по набору `equipment_id + part_id + char_id`. Поэтому несколько одинаковых характеристик одного типа для одного оборудования нельзя без изменения схемы записывать отдельными строками с одинаковыми `part_id` и `char_id`.

До изменения схемы применяется правило:

- для дисков, IP-адресов, номеров мониторов и дат мониторов допускается хранить несколько значений в одной записи `value_text`, разделяя их переносом строки;
- отдельные физические мониторы и ИБП должны храниться не как повторяющиеся характеристики, а как отдельные записи `equipment`;
- если требуется строго хранить несколько дисков отдельными строками, необходимо предварительно изменить модель характеристик: добавить порядковый номер/экземпляр компонента или отдельную таблицу компонентов.

### 4.2. Разделители на листе Принтеры

- **`\n`** встречается в столбцах: Пользователь, Оргтехника, Инвент. № принтера, IP адрес, Сетевой пароль администратора, Принтер в ведомости бух. Для Пользователь — первая строка как full_name; для пароля — не загружаем; для остальных — по контексту (одна запись или разбиение).
- **Запятая** — в названиях оргтехники (модель, скобки с параметрами), в примечаниях; не трактовать как разделитель списков для загрузки в отдельные записи, хранить как единое значение.

### 4.3. Семантика

Одна строка листа Принтеры = одна запись **equipment** (equipment_type = «Принтер» или «МФУ»), inventory_number из столбца 5 только если он уникален. При отсутствии или повторяющемся учетном признаке формируется внутренний уникальный номер `МЦ.04-prn-XXX`, исходное значение сохраняется в description/характеристике.
