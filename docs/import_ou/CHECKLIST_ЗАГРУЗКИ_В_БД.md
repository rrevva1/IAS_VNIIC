# Чек-лист загрузки в БД

Короткий операционный чек-лист для администратора перед чистовой загрузкой и после неё.

Основной регламент: `docs/import_ou/РЕГЛАМЕНТ_ЗАГРУЗКИ_В_БД.md`.

**Канал для «Основной Учет.xlsx»:** только `scripts/load_ou_main.py` (не web-импорт из «Учёт ТС»).

---

## 1) До запуска

- [ ] БД `ias_vniic` доступна, схема `tech_accounting` создана.
- [ ] Применены миграции Yii2 (`php yii migrate`) — таблицы `equipment_types`, `equipment_links`, `equipment_import_logs` и др.
- [ ] Для **чистовой** загрузки выполнена очистка: `php yii purge/keep-admin --force=1` (или пересоздание БД).
- [ ] Проверены таблицы: `equipment`, `users`, `locations`, `part_char_values`, `equipment_links`.
- [ ] Проверены справочники: `dic_equipment_status` (есть `in_use`), `spr_parts`, `spr_chars`, `equipment_types` (при схеме приложения), `roles`.
- [ ] Подготовлен файл источника (`Основной Учет.xlsx` или `ОУ.xlsx` того же формата); задан `OU_MAIN_EXCEL` при нестандартном пути.
- [ ] Установлены зависимости Python: `openpyxl`, `psycopg2-binary`.
- [ ] Подтверждён режим: чистовая после очистки БД или повторный прогон (идемпотентность по `inventory_number`).
- [ ] Актуален `РЕГЛАМЕНТ_ПАРСИНГА.md`.

---

## 2) Запуск

- [ ] Опционально — тест: `python3 scripts/load_ou_test_20rows.py` на `ОУ_тест.xlsx` до чистового прогона.
- [ ] Полная загрузка: `python3 scripts/load_ou_main.py` (лог сохранён, например `tee logs/load_ou_main_*.log`).
- [ ] В логе зафиксировано число связей ПК → монитор/ИБП (шаг 7, регламент §5.1).
- [ ] Если связи не созданы (старый прогон): `python3 scripts/link_ou_kits_only.py` с тем же `OU_MAIN_EXCEL`.
- [ ] При схеме `equipment_type_id` типы техники согласованы со справочником `equipment_types`.

---

## 3) Контроль после загрузки

- [ ] В `equipment` нет дубликатов `inventory_number`.
- [ ] Загружены типы: ПК/ноутбук/моноблок, монитор, ИБП, принтер/МФУ.
- [ ] Проверены `responsible_user_id` и `location_id` (выборочно).
- [ ] Проверены `part_char_values`: ЦП, ОЗУ, накопитель (столбец «Диск»), ОС, IP, имя ПК.
- [ ] Повторяющиеся признаки (МЦ.04, НИИСУ и т.п.) не вызвали конфликта; исходные значения в описании/характеристиках.
- [ ] **Комплекты связаны полностью:** у каждой строки-ПК столько связей `monitor`, сколько задаёт `monitor_kit_entries` (регламент §5.1.5); столько связей `ups`, сколько ИБП в «Другая техника».
- [ ] В stdout: «мониторов в источнике» = «создано записей мониторов при импорте».
- [ ] Пример: 2 модели в «Монитор» через `\n` → 2 записи «Монитор» + 2 связи `monitor`.
- [ ] **Не завышать счётчик:** при одной модели в «Монитор» и заполненной колонке ведомости («Монитор в ведомости бух.», напр. `МЦ.04.1`) — **1** монитор в связке (проверка: Аптекарева и аналоги с `НИИСУ` в «№ монитора»).
- [ ] В гриде «Учёт ТС» у ПК отображаются привязанные мониторы; счётчики «Мониторы (шт)» / «ИБП (шт)» соответствуют источнику.
- [ ] Протокол: сохранён лог stdout; при web-дозагрузке — запись в `equipment_import_logs`.
- [ ] Ошибки и предупреждения в логе разобраны.

---

## 4) Критерии успешности

- [ ] Нет блокирующих ошибок загрузки.
- [ ] Нет нарушений уникальности `inventory_number`.
- [ ] Данные по АРМ и Принтерам соответствуют источнику и отображаются в системе.
- [ ] Выполнена обязательная связка комплектов (регламент §5.1): `equipment_links` не пуста там, где в OУ у ПК есть мониторы/ИБП.
- [ ] Результат подтверждён ответственным за данные.
