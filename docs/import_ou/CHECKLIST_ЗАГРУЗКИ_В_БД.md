# Чек-лист загрузки в БД

Короткий операционный чек-лист для администратора перед чистовой загрузкой и после неё.

Основной регламент: `docs/import_ou/РЕГЛАМЕНТ_ЗАГРУЗКИ_В_БД.md`.

---

## 1) До запуска

- [ ] БД `ias_vniic` доступна, схема `tech_accounting` создана.
- [ ] Проверены таблицы: `equipment`, `users`, `locations`, `part_char_values`.
- [ ] Проверены справочники: `dic_equipment_status`, `spr_parts`, `spr_chars`.
- [ ] Подготовлен файл `Основной Учет.xlsx` (актуальная версия).
- [ ] Подтвержден режим загрузки: чистовая после очистки БД или повторный прогон.
- [ ] Подтвержден документ правил: `РЕГЛАМЕНТ_ПАРСИНГА.md`.

---

## 2) Запуск

- [ ] Для полной загрузки выполнено: `python3 scripts/load_ou_main.py`.
- [ ] Для тестовой выборки (опционально): `python3 scripts/load_ou_test_20rows.py`.
- [ ] Лог запуска сохранен (stdout/файл), если DB-протокол не ведется автоматически.

---

## 3) Контроль после загрузки

- [ ] В `equipment` нет дубликатов `inventory_number`.
- [ ] Загружены активы основных типов: ПК/ноутбук/моноблок, монитор, ИБП, принтер/МФУ.
- [ ] По выборке проверены связи ответственный (`responsible_user_id`) и помещение (`location_id`).
- [ ] По выборке проверены характеристики в `part_char_values` (ЦП, ОЗУ, Диск, ОС, IP, Имя ПК).
- [ ] Повторяющиеся учетные признаки (МЦ.04/НИИСУ/и т.п.) сохранены как исходные значения, а не как конфликтующие уникальные номера.
- [ ] Проверены ошибки/предупреждения в протоколе запуска.

---

## 4) Критерии успешности

- [ ] Нет блокирующих ошибок загрузки.
- [ ] Нет нарушений уникальности `inventory_number`.
- [ ] Данные по АРМ и Принтерам доступны в системе и соответствуют источнику.
- [ ] Результат подтвержден ответственным за данные.
