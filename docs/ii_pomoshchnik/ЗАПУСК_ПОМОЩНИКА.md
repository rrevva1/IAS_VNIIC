# Запуск ИИ-помощника

## Общие сведения

Помощник встроен в основное приложение (PHP/Yii) и не требует отдельного сервиса. Запросы обрабатываются контроллером `AssistantController`: парсинг интентов по ключевым словам и шаблонам, выборка данных из БД. Помощник ориентируется по **направлениям** (заявки, техника по ответственному, техника по локациям, список кабинетов, список пользователей, справка) и при неоднозначном запросе показывает подсказки с примерами. При включённой локальной LLM (LM Studio) для нераспознанных запросов используется структурированный контекст системы и имя текущего пользователя, чтобы модель предлагала примеры запросов по направлениям.

## Быстрый старт

1. **Запустить веб-приложение ИАС** (как обычно: PHP-сервер, доступ к БД).

2. **В ИАС:** войти под пользователем (в т. ч. администратором), справа внизу нажать кнопку **«Помощник»**, ввести запрос (например: «мои заявки», «справка», «статистика заявок», «техника Печерского», «список кабинетов»).

Отдельный сервис или второй процесс **не нужны** — всё выполняется в PHP.

## Доступ под администратором

Кнопка «Помощник» и панель чата доступны **всем авторизованным пользователям**. Права на данные те же: админ и оператор видят все заявки и технику; обычный пользователь — только свои заявки (и где он исполнитель) и только свою технику по запросу «техника [ФИО]».

## Подключение локальной модели (LM Studio, Gemma 3)

Если запрос не удаётся однозначно распознать по шаблонам, помощник может отправить его в локальную модель (например **LM Studio** с **Gemma 3**). Это опционально и настраивается переменными окружения для веб-сервера/PHP. Модель получает структурированный контекст: описание направлений запросов (заявки, техника по ответственному, техника по локациям, справка, список кабинетов, список пользователей) и примеры формулировок. Ответ модели используется только как текст подсказки; данные по-прежнему отдаёт приложение по распознанным интентам.

### Шаг 1: Запуск модели в LM Studio

1. Откройте **LM Studio**.
2. Загрузите и выберите модель (например **Gemma 3**).
3. Включите **Local Server** и убедитесь, что сервер слушает порт **1234** (по умолчанию).

API доступен по адресу: `http://localhost:1234/v1`.

### Шаг 2: Настройка приложения

Задайте переменные окружения **в среде, где запущен PHP/веб-сервер** (не в отдельном bat-файле помощника — его больше нет).

| Переменная   | Значение по умолчанию       | Описание |
|-------------|-----------------------------|----------|
| `LLM_ENABLED` | — (выключено)              | Включить вызов LLM: `1`, `true` или `yes` |
| `LLM_BASE_URL` | `http://localhost:1234/v1` | URL OpenAI-совместимого API (LM Studio) |
| `LLM_MODEL` | —                           | Имя модели в LM Studio (например `gemma-3`). Пусто — модель по умолчанию сервера |
| `LLM_API_KEY` | —                          | Для LM Studio обычно не нужен |

**Пример (CMD перед запуском PHP/сервера):**

```bat
set LLM_ENABLED=1
set LLM_BASE_URL=http://localhost:1234/v1
set LLM_MODEL=gemma-3
```

**Пример (PowerShell):**

```powershell
$env:LLM_ENABLED = "1"
$env:LLM_BASE_URL = "http://localhost:1234/v1"
$env:LLM_MODEL = "gemma-3"
```

Параметры читаются в `config/params.php` и используются компонентом `app\components\assistant\LlmClient`. Вызов ИИ выполняется при неопределённом интенте (см. раздел «Если помощник не обращается к ИИ» ниже).

### Шаг 3: Проверка

1. Запустите сервер в LM Studio и загрузите модель.
2. Запустите ИАС с заданными переменными.
3. В помощнике введите запрос не из шаблонов (например: «Расскажи про заявки»). Ответ должен сгенерировать локальная модель.

### Важно

- Сначала запускается **сервер в LM Studio**, затем — веб-приложение ИАС.
- Имя модели (`LLM_MODEL`) должно совпадать с именем в LM Studio (список: GET `http://localhost:1234/v1/models`).
- **Когда вызывается ИИ:** только при **неопределённом интенте** (`intent === null`), т.е. когда запрос не попал ни в один шаблон (например «привет», «расскажи про заявки»). Если запрос распознан (например «мои заявки», «кабинет 306»), ответ формируется без вызова модели.
- **Включение LLM:** при не заданном `LLM_ENABLED` вызов модели **включён по умолчанию**, если `LLM_BASE_URL` содержит `localhost:1234` или `127.0.0.1:1234`. Явно включить: `LLM_ENABLED=1`. Выключить: `LLM_ENABLED=0`.

### Если помощник не обращается к ИИ

1. **Проверить переменные** в среде PHP/веб-сервера: `LLM_ENABLED=1` или не задавать (при базовом URL localhost:1234 будет включено).
2. **Проверить запрос:** ввести фразу **не из шаблонов** (например «привет» или «что умеешь») — для таких запросов вызывается LLM.
3. **Лог приложения** `ias_uch_vnii/runtime/logs/app.log`: при отключённой LLM — запись «LlmClient: LLM disabled by config»; при ошибке запроса к LM Studio — «LlmClient: request failed for …».
4. **LM Studio:** сервер запущен, порт 1234, модель загружена.

## Векторный RAG (ChromaDB), опционально

При неопределённом запросе помощник может дополнять контекст для LLM **релевантными фрагментами из БД**, найденными по смыслу (векторный поиск). Для этого нужны Python 3 и предварительно построенный индекс ChromaDB.

### Требования

- **Python 3** (в PATH или задан в конфиге).
- Установка зависимостей в отдельном окружении (рекомендуется venv):

```bash
cd ias_uch_vnii/scripts
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
# source venv/bin/activate
pip install -r requirements.txt
```

В `requirements.txt`: chromadb, sentence-transformers (модель для русского языка — intfloat/multilingual-e5-base).

### Настройка

В среде PHP или в `config/params.php` задайте:

| Переменная / параметр | По умолчанию | Описание |
|----------------------|--------------|----------|
| `LLM_USE_VECTOR_RAG` / `llm_use_vector_rag` | выключено | Включить векторный поиск: `1`, `true`, `yes` |
| `RAG_VECTOR_DB_PATH` / `rag_vector_db_path` | `@runtime/chroma_db` | Каталог ChromaDB (алиас или абсолютный путь) |
| `RAG_SCRIPTS_PATH` / `rag_scripts_path` | `@app/scripts` | Каталог со скриптами `build_vector_db.py`, `search_context.py` |
| `RAG_TOP_K` / `rag_top_k` | 5 | Число чанков в ответе поиска |
| `RAG_PYTHON_BINARY` / `rag_python_binary` | — | Исполняемый файл Python (пусто — python/python3 из PATH) |

### Построение и обновление индекса

1. Убедитесь, что Python 3 доступен в PATH (или задайте `RAG_PYTHON_BINARY` в конфиге/среде — полный путь к `python.exe` или `py.exe`). На Windows при установке Python через магазин или python.org в консоли обычно доступна команда `py -3`.

2. Первичное построение индекса (экспорт таблиц из БД и создание векторной БД):

```bash
cd ias_uch_vnii
php yii rag/build-index
```

3. При значительных изменениях данных в БД команду можно запускать повторно (индекс пересоздаётся). Для автоматического обновления можно добавить вызов в cron или планировщик задач.

Каталог ChromaDB и временные файлы запросов не должны быть доступны из веб-корня; по умолчанию используется `runtime/chroma_db`.

## Справка по запросам

Помощник ориентируется по направлениям. Основные примеры:

- **Заявки:** «Мои заявки», «Заявки где я исполнитель», «Заявки за месяц», «Открытые заявки», «Статистика заявок», «Покажи заявки».
- **Техника по ответственному:** «Техника [ФИО]», «Покажи технику Печерского», «Что закреплено за Ивановым».
- **Техника по локации:** «Техника в кабинете 203», «Техника по кабинетам», «Что в серверной».
- **Справочно:** «Список кабинетов», «Список пользователей», «Справка».
