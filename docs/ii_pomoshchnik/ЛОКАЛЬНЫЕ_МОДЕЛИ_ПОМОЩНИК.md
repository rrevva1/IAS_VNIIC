# Локальные русскоязычные модели для ИИ-помощника

Документ фиксирует варианты небольших русскоязычных моделей (Hugging Face), пригодных для ответов по смыслу без передачи данных наружу. В ИАС помощник реализован на PHP и по умолчанию использует LM Studio (OpenAI-совместимый API). При необходимости интеграции перечисленных ниже моделей потребуется вызов из PHP (внешний процесс или HTTP-сервис).

---

## 1. Рекомендуемый вариант: экстрактивный QA (ответ из контекста)

**Назначение:** пользователь задаёт вопрос — модель находит ответ в переданном тексте (справка, описание системы) и возвращает фрагмент. Ответ всегда опирается на ваш контекст, «галлюцинаций» нет.

### Модель: RuBERT SberQuAD

| Параметр | Значение |
|----------|-----------|
| **ID на Hugging Face** | `MilyaShams/rubert-russian-qa-sberquad` |
| **Размер** | ~0.2B параметров |
| **Задача** | Question Answering (извлечение ответа из контекста) |
| **Базовая модель** | DeepPavlov/rubert-base-cased |
| **Обучающие данные** | SberQUAD (русский аналог SQuAD) |
| **Оценки** | F1 ~84.8, Exact Match ~66.6 по данным датасета |
| **Ориентир по RAM** | ~1–2 GB (CPU допустим) |

**Ссылка:** https://huggingface.co/MilyaShams/rubert-russian-qa-sberquad

**Идея интеграции:**  
Когда парсер интентов не распознал запрос (`intent === null`) или запрос похож на вопрос («как», «что», «где»), передавать в модель контекст (HELP_TEXT + описание системы) и вопрос пользователя. В ИАС вызов модели выполняется в PHP (LlmClient → LM Studio). Ниже — пример вызова такой модели из скрипта (для справки; не входит в состав приложения).

```python
from transformers import pipeline

qa = pipeline("question-answering", model="MilyaShams/rubert-russian-qa-sberquad")

context = """
В системе учёта технических средств вы можете создать заявку в разделе «Заявки»
по кнопке создания заявки; укажите описание и при необходимости прикрепите файлы.
Просматривать заявки можно в разделе «Заявки». Помощник понимает запросы:
«Мои заявки», «Заявки за месяц», «Открытые заявки», «Статистика заявок».
"""

out = qa(question="Как создать заявку?", context=context)
# out["answer"], out["score"]
```

**Зависимости:** `transformers`, `torch`, `sentencepiece`. При первом запуске модель скачается с Hugging Face.

## 2. Альтернатива: генеративная модель (свободный ответ)

Подходит, если нужны развёрнутые формулировки «своими словами», а не только цитата из контекста. Требует больше ресурсов и аккуратности с промптом, чтобы модель не уходила от темы.

### Вариант A: ruDialoGPT-small (диалог)

| Параметр | Значение |
|----------|----------|
| **ID на Hugging Face** | `t-bank-ai/ruDialoGPT-small` (Tinkoff/T-Bank) |
| **Размер** | ~124M параметров, ~0.6 GB VRAM |
| **Задача** | text-generation, диалог |
| **Контекст** | 3 реплики (формат диалога) |
| **Формат промпта** | `@@ПЕРВЫЙ@@` — пользователь, `@@ВТОРОЙ@@` — бот |

**Ссылка:** https://huggingface.co/t-bank-ai/ruDialoGPT-small

**Особенность:** модель обучена на диалогах; для «знаний» системы контекст можно задать одной репликой ПЕРВОГО («Справка: … Вопрос пользователя: …»), затем генерировать ответ ВТОРОГО. Качество следования строго заданному контексту может быть хуже, чем у QA-модели.

**Минимальный пример (справочно):**

```python
from transformers import AutoTokenizer, AutoModelForCausalLM

tokenizer = AutoTokenizer.from_pretrained("t-bank-ai/ruDialoGPT-small")
model = AutoModelForCausalLM.from_pretrained("t-bank-ai/ruDialoGPT-small")

# Контекст справки + вопрос как одна реплика пользователя
prompt = (
    "@@ПЕРВЫЙ@@ Справка: В системе можно создать заявку в разделе Заявки. "
    "Пользователь спрашивает: Как создать заявку? @@ВТОРОЙ@@"
)
inputs = tokenizer(prompt, return_tensors="pt")
out = model.generate(
    **inputs,
    max_new_tokens=80,
    do_sample=True,
    top_p=0.95,
    temperature=0.8,
    repetition_penalty=1.2,
    pad_token_id=tokenizer.eos_token_id,
)
reply = tokenizer.decode(out[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)
```

### Вариант B: TinyLlama-1.1B-Chat-RU (чат с ролями)

| Параметр | Значение |
|----------|----------|
| **ID на Hugging Face** | `Arman123/TinyLlama-1.1B-Chat-RU` |
| **Размер** | 1.1B параметров |
| **Задача** | text-generation, чат (instruct-style) |
| **Формат** | Chat template: `<|im_start|>system/user/assistant`, `<|im_end|>` |

**Ссылка:** https://huggingface.co/Arman123/TinyLlama-1.1B-Chat-RU

Удобно передавать системный промпт (описание системы и правил) и вопрос пользователя; модель генерирует ответ ассистента. Требует больше памяти, чем ruDialoGPT-small (ориентир 2–4 GB).

## 3. Более тяжёлые варианты (при наличии ресурсов)

- **Saiga (7B/8B)** — русскоязычные чат-модели на базе LLaMA. Нужна квантизация (GGUF Q4/Q5) для запуска на 8–16 GB RAM. Подходят для более сложных формулировок и многоходового диалога.
- **Vikhr-7B-instruct** — русский instruct-модель на Hugging Face.

Для первого этапа и «ответов по сути» без выноса данных за периметр достаточно **RuBERT QA** (раздел 1) или **ruDialoGPT-small** (раздел 2A).

## 5. Рекомендация по внедрению

1. **Старт:** при необходимости интеграции модели **MilyaShams/rubert-russian-qa-sberquad** в помощник — реализовать вызов из PHP (внешний процесс или HTTP-сервис), при `intent === null` передавать в модель контекст (HELP_TEXT + выдержки из документации) и вопрос пользователя; возвращать ответ и при необходимости score для отсечения слабых ответов. В текущей реализации используется LM Studio и LlmClient (PHP).
2. **Контекст:** хранить текст справки и описание системы в одном месте (например, константа или файл), при необходимости разбивать на чанки по длине ограничения модели (RuBERT обычно до 512 токенов).
3. **Офлайн:** при отсутствии доступа к интернету после первого скачивания можно использовать кэш Hugging Face (`HF_HOME` / `TRANSFORMERS_CACHE`) или положить склонированный репозиторий модели в локальную папку и загружать через `from_pretrained("/path/to/model")`.
