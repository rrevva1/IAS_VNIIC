# Окружение ИИ-помощника

Пошаговая настройка окружения для работы встроенного ИИ-помощника ИАС. Для базового режима (свободный чат с ориентацией в предметной области) **Python не требуется**.

---

## 1. Минимальный набор (без Python)

### 1.1. PHP и веб-приложение

- Используется штатная среда проекта: PHP 8.x, Yii2, PostgreSQL.
- Дополнительные PHP-зависимости для помощника не нужны.

### 1.2. Локальная LLM (LM Studio)

1. Установите [LM Studio](https://lmstudio.ai/).
2. Скачайте и выберите модель (например Gemma 3 или другую русскоязычную из [ЛОКАЛЬНЫЕ_МОДЕЛИ_ПОМОЩНИК.md](ЛОКАЛЬНЫЕ_МОДЕЛИ_ПОМОЩНИК.md)).
3. Включите **Local Server** и убедитесь, что сервер слушает порт **1234**.

### 1.3. Переменные окружения

Задайте переменные **в среде, откуда запускается PHP/веб-сервер**:

| Переменная     | Значение              | Описание |
|----------------|------------------------|----------|
| `LLM_ENABLED`  | `1`                    | Включить вызов LLM |
| `LLM_BASE_URL` | `http://localhost:1234/v1` | URL API (LM Studio) |
| `LLM_MODEL`    | имя модели в LM Studio | Например `gemma-3` |

**Windows (CMD):**

```bat
set LLM_ENABLED=1
set LLM_BASE_URL=http://localhost:1234/v1
set LLM_MODEL=gemma-3
```

**Windows (PowerShell):**

```powershell
$env:LLM_ENABLED = "1"
$env:LLM_BASE_URL = "http://localhost:1234/v1"
$env:LLM_MODEL = "gemma-3"
```

**Linux/macOS (bash):**

```bash
export LLM_ENABLED=1
export LLM_BASE_URL=http://localhost:1234/v1
export LLM_MODEL=gemma-3
```

### 1.4. Текстовый RAG (ориентация в сущностях)

Работает без установки: списки пользователей, локаций и статусов заявок из БД подставляются в контекст LLM автоматически (параметр `llm_use_rag` включён по умолчанию). Выключить при необходимости: `LLM_USE_RAG=0`.

### 1.5. История диалога

По умолчанию включена: последние пары «запрос — ответ» хранятся в сессии и передаются в LLM для контекста свободного чата. Параметры:

| Переменная             | По умолчанию | Описание |
|------------------------|--------------|----------|
| `LLM_USE_HISTORY`      | включено     | Выключить: `0` |
| `LLM_HISTORY_MAX_PAIRS`| `10`         | Максимум пар в истории |

### 1.6. Проверка

1. Запустите **сначала** LM Studio (Local Server на порту 1234), затем веб-приложение ИАС с заданными переменными.
2. Войдите в ИАС, откройте помощника (кнопка «Помощник»).
3. Введите запрос не из шаблонов (например: «Привет», «Расскажи про заявки»). Должен прийти ответ от локальной модели с учётом контекста системы.
4. Задайте уточняющий вопрос по тому же диалогу — ответ должен учитывать историю.

Подробнее: [ЗАПУСК_ПОМОЩНИКА.md](ЗАПУСК_ПОМОЩНИКА.md).

## 2. Векторный RAG (опционально, нужен Python)

Векторная БД (ChromaDB) позволяет дополнять контекст LLM **релевантными фрагментами из БД** по семантическому поиску. По умолчанию **выключено** (`llm_use_vector_rag` = false), чтобы не требовать Python при первом запуске.

### 2.1. Когда имеет смысл включать

- Семантический поиск по текстам заявок и описаний оборудования.
- Подключение фрагментов внутренней документации (ТЗ, описание системы) к ответам помощника.

### 2.2. Установка

1. Установите **Python 3** (в PATH или укажите путь в `RAG_PYTHON_BINARY`).
2. В каталоге `ias_uch_vnii/scripts`:
   - `python -m venv venv`
   - Активация: Windows `venv\Scripts\activate`, Linux/macOS `source venv/bin/activate`
   - `pip install -r requirements.txt`
3. Построение индекса (из корня приложения `ias_uch_vnii`):
   - `php yii rag/build-index`
4. Включение: задать `LLM_USE_VECTOR_RAG=1` в окружении PHP/веб-сервера.

Подробнее: раздел «Векторный RAG (ChromaDB)» в [ЗАПУСК_ПОМОЩНИКА.md](ЗАПУСК_ПОМОЩНИКА.md).

---

## 3. Чек-лист перед запуском

- [ ] PHP и ИАС поднимаются, БД доступна.
- [ ] LM Studio установлен, модель загружена, Local Server на порту 1234.
- [ ] Переменные `LLM_ENABLED`, `LLM_BASE_URL`, `LLM_MODEL` заданы в среде веб-сервера.
- [ ] (Опционально) Для векторного RAG: Python 3, venv, `pip install -r requirements.txt`, `php yii rag/build-index`, `LLM_USE_VECTOR_RAG=1`.

После выполнения пунктов 1–3 помощник готов к работе в режиме свободного чата с ориентацией в предметной области (онтология + текстовый RAG; при включённом векторном RAG — также семантический поиск по данным).

## Как модель «знакомится» с данными БД

Чтобы модель в LM Studio могла отвечать на вопросы по реальным данным (в т.ч. «найди самый мощный процессор», «самый новый компьютер»), в контекст при каждом запросе подставляются актуальные срезы из БД. Способы:

| Способ | Что передаётся | Зачем |
|--------|----------------|-------|
| **Онтология (системный промт)** | Описание сущностей: пользователь, заявка, техника (с характеристиками ЦП, ОЗУ, дата), локация. Направления запросов, в т.ч. «аналитика по технике». | Модель понимает, что есть в системе и какие запросы допустимы. |
| **Текстовый RAG** | Списки: пользователи (ФИО), локации, статусы заявок. Плюс **сводка по технике**: до 15 единиц с характеристиками (ЦП, ОЗУ, диск, дата постановки). | Модель «видит» реальные имена, кабинеты и примеры техники с характеристиками; может отвечать на «самый мощный процессор» или «самый новый» по переданному срезу. Включено по умолчанию (без Python). |
| **Векторный RAG (опционально)** | При построении индекса (`php yii rag/build-index`) в документы по таблице `equipment` подмешиваются характеристики из `part_char_values` (ЦП, ОЗУ, диск). По запросу семантический поиск возвращает релевантные фрагменты. | Для больших объёмов данных и запросов по смыслу; требует Python и ChromaDB. |

Итог: для запросов вроде «найди самый мощный процессор в БД или самый новый» достаточно **онтологии + текстового RAG** (в нём уже есть сводка по технике с ЦП/ОЗУ/датой). Модель опирается только на переданный контекст и не придумывает записи. Векторный RAG расширяет возможности при большом количестве единиц техники.

## Как проиндексировать всю БД для ИИ

Чтобы ИИ «знал», как устроена БД и какие в ней данные, используются три уровня (все уже заложены в коде).

### Что передаётся модели без дополнительной настройки

- **Онтология** в системном промте: сущности (пользователь, заявка, техника, локация), типы локаций (кабинет, склад, серверная…), что у техники есть характеристики (ЦП, ОЗУ, дата).
- **Текстовый RAG** при каждом запросе подставляет актуальные данные из БД: список пользователей (ФИО), список локаций (название и тип), статусы заявок, сводка по технике (до 15 единиц с ЦП, ОЗУ, датой). Этого достаточно, чтобы модель ориентировалась в сущностях и могла отвечать на вопросы вроде «самый мощный процессор» или «какие кабинеты есть».

### Логика БД, которую «понимает» помощник

- **Локации:** в БД хранятся тип (`location_type`: кабинет, склад, серверная, лаборатория, другое) и название/код (`name`, `location_code`). Запрос «техника в помещении 314» или «в кабинете 314» ищет локацию с типом «кабинет» и номером/названием, содержащим «314», либо любую локацию с «314» в названии/коде (запасной поиск). Если помещения 314 нет в справочнике локаций, система вернёт «не найдено» — тогда нужно добавить запись в раздел локаций.
- **Техника:** привязана к локации (`location_id`) и к ответственному; характеристики (ЦП, ОЗУ, диск) хранятся в `part_char_values`.

### Векторная индексация «всей» БД (опционально)

Для семантического поиска по содержимому таблиц используется векторный индекс (ChromaDB). В индекс по умолчанию попадают таблицы из `config/params.php` (`rag_tables`): **tasks**, **equipment**, **locations**, **users**; для **equipment** в каждый документ дописываются характеристики из `part_char_values` (ЦП, ОЗУ, диск).

**Как проиндексировать:** установить Python 3 и зависимости (раздел «Векторный RAG» выше), выполнить `php yii rag/build-index`, включить `LLM_USE_VECTOR_RAG=1`. Чтобы добавить другие таблицы, в `rag_tables` в params добавить имена таблиц и снова выполнить `php yii rag/build-index`. Объём ограничивается параметром `rag_limit_per_table` (по умолчанию 1000 строк на таблицу).
