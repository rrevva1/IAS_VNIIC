# Реестр версий и дубликатов материалов ВКР (`docs/vkr`)

Документ фиксирует, какие файлы считать актуальными источниками правды, какие пары являются побайтовыми дубликатами (разное имя или путь), и какие артефакты относятся к черновым цепочкам сборки Word. Удаление «старого» выполняется вручную после согласования.

Дата сверки: 2026-04-20.

---

## 1. Текст глав (Markdown)

| Назначение | Актуальная версия (источник правды) | Примечание |

| Глава 1 | `export/docx/ВКР_глава_1_04.docx` + `Раздел_1_Анализ_проблемы_и_требования.md` | **Эталон оформленного текста и нумерации рисунков** — Word `ВКР_глава_1_04.docx` (при необходимости оформления — `ВКР_глава_1_04_ф.docx`). Markdown главы 1 выравнивается по этому DOCX (пути к рисункам — `export/named/png/fig_1_*.png`, реестр — `FIGURES_VKR_glava_1_03.md`). Дальнейшие правки: либо в Word с повторной выгрузкой в `.md`, либо в `.md` с переносом в Word вручную. |

## 3. Рисунки и диаграммы (`export/`)

### 3.1. Имена для Word и перечень вставок

Ориентир: `КОМПЛЕКТ_РИСУНКОВ_И_ТАБЛИЦ_ДЛЯ_WORD.md`.

**Глава 1 — эталонные растры из `ВКР_глава_1_04.docx`:** перечень имён и подписей — `export/named/png/FIGURES_VKR_glava_1_03.md` (файлы `fig_1_1_*.png` … `fig_1_8_*.png`). Старые имена вида `fig_1_2_asset_lifecycle.png` / `fig_1_4a_dfd_level1.png` могут относиться к прежней линейке сборки и **не** считаются каноном главы 1 после синхронизации с эталоном `ВКР_глава_1_04.docx`.

**Глава 2 и прочие иллюстрации:** каталоги

- `export/named/svg/`
- `export/named/png/` (прочие `fig_2_*` и др.)

### 3.2. Дубликаты по именованию `chapterN_fig_M` (удалены)

Ранее содержимое `export/svg/chapter1_fig_1.svg` совпадало с `export/named/svg/fig_1_1_transition_to_ias.svg` (и аналогично для PNG). Каталоги **`export/png/`** и **`export/svg/`** с префиксом `chapterN_fig_M` **удалены** (2026-04-06); превью HTML `export/html/vkr_glavy_1_2.html` переведён на относительные пути к `export/named/png/`. Канонические имена файлов для вставки в Word — в `КОМПЛЕКТ_РИСУНКОВ_И_ТАБЛИЦ_ДЛЯ_WORD.md`.

### 3.3. IDEF0 (рис. 1.6–1.7): три визуальных варианта (не дубликаты)

Содержимое **различается** (разные SHA-256):

| Вариант | Каталог | Назначение |
|---------|---------|------------|
| Основной предпросмотр / вставка по комплекту | `export/preview/idef0/svg/` (и `png/`) | В `КОМПЛЕКТ_...` указаны имена `chapter1_fig_6_idef0_context.svg`, `chapter1_fig_7_idef0_decomposition.svg` |
| Строгий стиль | `export/strict-svg/`, `export/strict-png/` | Суффикс `_strict` в имени файла |
| Облегчённый стиль | `export/light-svg/`, `export/light-png/` | Суффикс `_light` |

В `export/named/png/` есть экспорт 1.6–1.7 и 1.8 в линейке «fig_1_*»; при расхождении с `preview/idef0` ориентиром для подписей в Word остаётся `КОМПЛЕКТ_РИСУНКОВ_И_ТАБЛИЦ_ДЛЯ_WORD.md`.

### 3.4. Исходники диаграмм

**Актуально:** `export/mermaid-src/*.mmd` — исходники для пересборки SVG/PNG при изменении текста глав.

Для главы 2 актуальны исходники `chapter2_fig_1.mmd` ... `chapter2_fig_7.mmd` в соответствии с обновлённым комплектом вставок в Word.

### 3.5. HTML

Файлы в `export/html/` (`vkr_glavy_1_2.html`, `vkr_glavy_1_2_png_polished.html`, `vkr_glavy_1_2_DOCX_skill_правки.html`) — предпросмотр; имя `*_DOCX_skill_правки` сохранено как в репозитории, содержание сверяют с `vkr_glavy_1_2.html` и Markdown-источниками. Служебные `*_check.txt` удалены (2026-04-06) как дубликаты текстовых выгрузок.

### 3.6. Правило синхронизации главы 2

Для второй главы следует использовать следующий порядок работы:

1. Содержательные правки вносятся сначала в `Раздел_2_Архитектурное_проектирование.md`.
2. После стабилизации текста изменения вручную переносятся в `export/docx/ВКР_глава_2_03.docx` (при необходимости — `ВКР_глава_2_03_ф.docx`) с сохранением пользовательских форматных правок.
3. Лишь после этого обновляется эталон полной сборки `export/docx/ВКР_1_2_01.docx` (либо пересборкой `build_vkr_docx.js`, либо вручную — по принятому регламенту).
4. При ручной правке `docx` без немедленного обновления Markdown такая правка считается временно несинхронизированной и должна быть отдельно сверена перед следующей сборкой.

## 4. Выполненная очистка репозитория (служебное)

Удалено без потери исходников проекта:

- все файлы AppleDouble `._*` под `docs/vkr/` (служебные метаданные macOS);
- `docs/vkr/export/.venv/` (локальное окружение Python, ~350 МБ);
- `docs/vkr/export/node_modules/` (зависимости npm для `export/build_vkr_docx.js`, ~120 МБ).

**2026-04-06:** удалены дубликаты Word (побайтовые копии при совпадении с основой, черновики PNG/черновик), копия `ВКР_главы_1_2.docx` в корне `docs/vkr/`, дубликат `Глава 1_Милованов_26.03.docx`, каталоги `export/png/` и `export/svg/`, служебные `export/html/*_check.txt`, файл с некорректным именем `export/light-png/pic 1.6 (1).png`. Удалён также альтернативный вариант полной сборки `ВКР_главы_1_2_DOCX_skill_сборка_01.docx` (отличался объёмом; при необходимости восстановить из истории git). Это **не** относится к текущему эталону `ВКР_1_2_01.docx`.

В `.gitignore` добавлены правила, чтобы указанные каталоги не попадали в коммиты. Для повторной сборки DOCX в каталоге `docs/vkr/export/` выполнить: `npm install` (при необходимости — создание `.venv` локально, не в репозитории).
